### 1.3 order-service 用券契约（ticketflow-order-service）

新增（不动 V5 下单主链路，契约可平滑接入主链路）：

| 文件 | 职责 |
|------|------|
| `client/CouponClient` | Feign 客户端：`/coupon/lock|use|return`，服务名 `ticketflow-coupon-service` |
| `dto/CouponOperateDto`、`vo/CouponOperateVo` | 契约 DTO（对齐 coupon 侧字段） |
| `dto/CouponOrderCreateDto`、`CouponOrderCancelDto`、`vo/CouponOrderVo` | 券订单演示接口 |
| `service/CouponOrderService` | 业务：锁券 → 抵扣金额计算 → 模拟支付 → 核销 / 取消退券 |
| `controller/CouponOrderController` | `POST /order/coupon/order`、`POST /order/coupon/cancel` |

**对接要点（落地的真实经验）**：
- coupon 侧 `Result` 成功码是 **200**，现有 `ApiResponse` 成功码是 **0**——Feign 反序列化后判断必须按 coupon 语义 `code==200`，代码里已加注释说明。
- 抵扣金额计算：`实付 = max(0, 原价 - 券面额)`（满减券），面额以 lock 返回的快照为准（防改价）。
- 锁券失败（券已用/被占用）抛异常 → 现有体系统一转 `-100`（`ApiResponse.error()` 默认值），业务语义正确（券不可复用被拦截）。

```
POST /order/coupon/order {userId:8001, couponNo:CP...121, amount:150.00}
→ {orderNo:2089602765713055749, originalAmount:150.00, discountAmount:20.00,
   payAmount:130.00, status:PAID}
```
- lock（防并发使用，返回面额快照 20）→ 计算实付 130 → use（核销）全流程经 Feign 真实完成。
- 券不可复用：同券再下单 → 拦截（lock 返回 50203 → 转 -100）。

### 2.4 退券三态闭环

```
1. lock（模拟下单未支付）        → code 200，金额 20
2. POST /order/coupon/cancel     → returnCoupon → status CANCELLED
3. DB 验证券状态：status=0(未使用) order_no=NULL，可再次 lock ✓
```
